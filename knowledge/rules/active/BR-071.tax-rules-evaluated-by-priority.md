# Tax Rules Evaluated by Priority

## Statement

When auto-assigning tax codes, tax rules are evaluated in priority order (highest first). The first matching rule determines the tax code.

## Rationale

Provides a deterministic and predictable mechanism for tax code assignment. Priority ordering allows overriding general rules with specific exceptions, supporting complex tax scenarios across different jurisdictions and product categories.

## Scope

- Applies to: All tax code auto-assignment rules (BC-TAX)
- Bounded Context: BC-TAX (Tax Management)
- Entities: TaxCode, TaxAutoAssignmentRule

## Conditions

- **WHEN** the system evaluates tax rules for a transaction
- **THEN** rules MUST be evaluated in descending priority order (highest priority number first)
- **AND** the first rule that matches the transaction determines the tax code
- **OTHERWISE** the transaction proceeds without an assigned tax code

## Pseudocode

```
function autoAssignTaxCode(transaction):
    rules = findTaxAutoAssignmentRules(ordered_by_priority_desc)
    
    for rule in rules:
        if rule.matches(transaction):
            return rule.tax_code_id
    
    return null // No matching rule found
```

## Exceptions

- If no rules match, the transaction may proceed with a manually assigned tax code or without a tax code if tax-exempt.
