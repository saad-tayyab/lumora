# Receiving Report Must Reference Valid PO

## Statement

A receiving report must reference a valid purchase order.

## Receiving reports without a valid PO reference would break the three-way matching process and prevent proper procurement tracking. This ensures every goods receipt can be traced back to its originating purchase order.

## Scope

- Applies to: All receiving reports (CON-PROC-004)
- Bounded Context: BC-PROC (Procurement)
- Entities: ReceivingReport, PurchaseOrder

## Conditions

- WHEN a receiving report is created
- THEN po_id MUST reference a valid existing purchase order
- OTHERWISE the receiving report is rejected with error `ERR_RR_INVALID_PO_REFERENCE`

## Pseudocode

```
function validateReceivingReportPO(rr):
    po = findPurchaseOrder(rr.po_id)
    if po == null:
        throw RRInvalidPOReferenceError(rr.id, rr.po_id)
```

## Exceptions

- None — this rule has no exceptions.
