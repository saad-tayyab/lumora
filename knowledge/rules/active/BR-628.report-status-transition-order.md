# Report Status Transition Order

## Statement

Report status must follow the sequence: draft -> active -> archived.

## Rationale

This enforces a controlled lifecycle for reports. Reports must be reviewed and activated before they can be used, and archived reports represent historical snapshots that should not be modified.

## Scope

- Applies to: All reports (CON-REPORT-001)
- Bounded Context: BC-REPORT (Reporting & Analytics)
- Entities: Report

## Conditions

- WHEN a report status transition is requested
- THEN the transition MUST follow the valid sequence
- OTHERWISE the transition is rejected with error `ERR_REPORT_INVALID_STATUS_TRANSITION`

## Pseudocode

```
function transitionReportStatus(report, newStatus):
    validTransitions = {
        'draft': ['active'],
        'active': ['archived'],
        'archived': []  // No transitions from archived
    }
    
    if newStatus not in validTransitions[report.status]:
        throw InvalidStatusTransitionError(report.id, report.status, newStatus)
    
    report.status = newStatus
    persist(report)
```

## Exceptions

- None — this rule has no exceptions.
